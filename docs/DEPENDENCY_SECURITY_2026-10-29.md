# Cloudflare development dependency remediation — 2026-10-29

Base: `cd15ff2d6a86656257c80e60b45032a6dfea6eba` (`main`).

The Cloudflare development toolchain pinned Undici 7.29.0, affected by
[GHSA-xjj6-f33q-929c](https://github.com/nodejs/undici/security/advisories/GHSA-xjj6-f33q-929c).
An excessive content-encoding chain followed by an early connection close could
crash the Node.js process despite catching the fetch rejection.

Use the supported Vite plugin v1 release instead of overriding Undici:

| Package | Before | After |
| --- | --- | --- |
| `@cloudflare/vite-plugin` | 1.51.1 | 1.66.0 |
| `wrangler` | 4.120.0 | 4.154.0 |
| `miniflare` | 5.20260801.1-alpha | 5.20261023.1-beta |
| `undici` | 7.29.0 | 7.30.1 |
| `workerd` | 1.20260801.1 | 1.20261023.1 |

The [Vite plugin release](https://github.com/cloudflare/workers-sdk/releases/tag/%40cloudflare%2Fvite-plugin%401.66.0)
also fixes its bundled remote-bindings copy of Undici. Wrangler 4.154.0 matches
the plugin's own exact dependency, keeping a single Miniflare/Undici chain.
The lockfile was generated by npm; there is no new override.

Miniflare no longer reads `MINIFLARE_REGISTRY_PATH`. Use
`CLOUDFLARE_DEV_REGISTRY_PATH` with the existing `.wrangler/registry` location.
The three direct Miniflare test fixtures use its exported
`convertV4MiniflareOptions()` adapter to preserve their Worker/D1 configuration
under the new constructor schema. Their assertions are unchanged.
